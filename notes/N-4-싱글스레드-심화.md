# N-4. 싱글 스레드 심화 — worker_threads · child_process · 스레드 풀

> 1-4에서 "노드는 I/O에 강하고 CPU 계산엔 약하다"고 했습니다.
> 이 노트는 그 **"약하다"를 해결하는 방법**입니다.
> 그리고 "노드는 싱글 스레드인가요?"라는 면접 단골 질문의 진짜 정답이기도 합니다.

---

## 1. 먼저 — 노드는 정말 싱글 스레드인가?

**정확히 말하면 "자바스크립트 코드를 실행하는 스레드가 하나"입니다.**

노드 내부에는 사실 여러 스레드가 있습니다.

| 구성 요소 | 스레드 | 하는 일 |
|---|---|---|
| 이벤트 루프 | **1개** | 우리가 쓴 JS 코드 실행 |
| libuv 스레드 풀 | **기본 4개** | 파일 I/O, 일부 crypto, DNS 조회 등 |
| worker_threads | 우리가 만드는 만큼 | CPU 작업 분산 |

그래서 면접에서 이렇게 답하면 됩니다:

> "이벤트 루프는 싱글 스레드지만, 내부적으로 libuv 스레드 풀이 있어서 파일 I/O 같은 건
> 멀티 스레드로 처리됩니다. CPU 집약적인 작업은 worker_threads로 별도 스레드에 넘길 수 있고요."

---

## 2. 문제 재현 — CPU 작업이 서버를 막는다

```js
// blocking.js
const http = require('http');

function heavyTask() {
  let sum = 0;
  for (let i = 0; i < 5_000_000_000; i++) sum += i;   // 수 초 걸림
  return sum;
}

http.createServer((req, res) => {
  if (req.url === '/heavy') {
    const result = heavyTask();       // ← 이 동안 서버 전체가 멈춤
    res.end(String(result));
  } else {
    res.end('빠른 응답');
  }
}).listen(8080);
```

`/heavy` 요청 하나가 도는 동안 `/` 요청도 전부 대기합니다. **1-4에서 본 그 현상**인데, 이번엔 파일 I/O가 아니라 순수 계산이라 비동기로 바꿔도 해결되지 않습니다. 계산은 어차피 CPU를 써야 하니까요.

---

## 3. worker_threads — 계산을 다른 스레드로

### 기본 사용법

```js
// worker.js — 별도 스레드에서 돌 코드
const { parentPort, workerData } = require('worker_threads');

function heavyTask(limit) {
  let sum = 0;
  for (let i = 0; i < limit; i++) sum += i;
  return sum;
}

parentPort.postMessage(heavyTask(workerData.limit));
```

```js
// server.js
const http = require('http');
const { Worker } = require('worker_threads');

function runWorker(limit) {
  return new Promise((resolve, reject) => {
    const worker = new Worker('./worker.js', { workerData: { limit } });
    worker.on('message', resolve);
    worker.on('error', reject);
    worker.on('exit', (code) => {
      if (code !== 0) reject(new Error(`워커 종료 코드 ${code}`));
    });
  });
}

http.createServer(async (req, res) => {
  if (req.url === '/heavy') {
    const result = await runWorker(5_000_000_000);   // ← 메인 스레드는 안 막힘
    res.end(String(result));
  } else {
    res.end('빠른 응답');
  }
}).listen(8080);
```

이제 `/heavy`가 도는 동안에도 `/`는 즉시 응답합니다.

### 주의할 점

- **워커 생성 비용이 있습니다.** 요청마다 워커를 만들면 오히려 느려질 수 있어요. 실무에선 **워커 풀**을 만들어 재사용합니다 (`piscina` 같은 라이브러리가 이걸 해줍니다).
- 메인과 워커는 **메모리를 공유하지 않습니다.** `postMessage`로 주고받는 데이터는 복사됩니다. 큰 데이터는 `SharedArrayBuffer`를 쓰거나 아예 넘기지 않는 설계가 필요합니다.
- **CPU 작업에만 의미가 있습니다.** I/O는 이미 논블로킹이라 워커로 옮겨도 이득이 없습니다.

### 언제 쓰나

| 상황 | worker_threads |
|---|---|
| 이미지 리사이징·인코딩 | ✅ |
| 대용량 CSV 파싱·집계 | ✅ |
| 암호화 해시 반복 계산 | ✅ |
| DB 조회 | ❌ (이미 논블로킹) |
| 파일 읽기 | ❌ (이미 논블로킹) |
| 외부 API 호출 | ❌ (이미 논블로킹) |

## 4. child_process — 아예 다른 프로세스 실행

worker_threads가 "같은 프로세스 안의 다른 스레드"라면, child_process는 **완전히 별개의 프로그램**을 실행합니다. 다른 언어로 짠 프로그램도 돌릴 수 있어요.

### exec — 셸 명령 실행

```js
const { exec } = require('child_process');

exec('ls -al', (err, stdout, stderr) => {
  if (err) return console.error(err);
  console.log(stdout);
});
```

### spawn — 스트림으로 주고받기 (대용량에 적합)

```js
const { spawn } = require('child_process');

const python = spawn('python3', ['script.py']);

python.stdout.on('data', (data) => {
  console.log(`결과: ${data}`);
});
python.stderr.on('data', (data) => {
  console.error(`에러: ${data}`);
});
python.on('close', (code) => {
  console.log(`종료 코드 ${code}`);
});
```

| 함수 | 특징 | 언제 |
|---|---|---|
| `exec` | 결과를 버퍼에 모아 한 번에 | 출력이 작을 때 |
| `spawn` | 스트림으로 실시간 | 출력이 크거나 길 때 |
| `fork` | 노드 프로세스 전용, IPC 내장 | 노드끼리 통신할 때 |

> ⚠️ **보안**: `exec`에 사용자 입력을 그대로 넣지 마세요. 명령어 주입(command injection) 취약점이 됩니다.
> 사용자 입력이 들어가야 한다면 `spawn`에 **인자 배열로** 전달하세요.

## 5. libuv 스레드 풀 — 이미 쓰고 있던 멀티 스레드

`fs.readFile`은 비동기죠. 그런데 **누가 파일을 읽고 있을까요?**

이벤트 루프가 아니라 **libuv 스레드 풀**입니다. 기본 4개 스레드가 백그라운드에서 실제 파일 읽기를 담당하고, 다 되면 콜백을 이벤트 루프의 큐에 넣어줍니다.

### 스레드 풀을 쓰는 작업들

- `fs` 모듈의 대부분 (네트워크 I/O는 제외)
- `crypto.pbkdf2`, `crypto.scrypt` 등 일부 암호화
- `zlib` 압축
- `dns.lookup`

### 크기 조절

```bash
UV_THREADPOOL_SIZE=8 node app.js
```

```js
// 코드 내에서는 첫 사용 전에 설정해야 적용됨
process.env.UV_THREADPOOL_SIZE = 8;
```

### 확인 실험

```js
const crypto = require('crypto');
const start = Date.now();

for (let i = 0; i < 8; i++) {
  crypto.pbkdf2('pw', 'salt', 1_000_000, 64, 'sha512', () => {
    console.log(i, Date.now() - start);
  });
}
```

기본값(4)으로 돌리면 **앞 4개가 먼저 끝나고, 뒤 4개가 그다음에 끝나는** 계단 모양이 나옵니다.
`UV_THREADPOOL_SIZE=8`로 올리면 8개가 비슷하게 끝나요. 스레드 풀이 실재한다는 증거입니다.

> **주의**: 무작정 늘리면 CPU 코어 수를 넘어가면서 컨텍스트 스위칭 비용만 커집니다.
> 보통 **코어 수 정도**가 상한선입니다.

## 6. 정리 — 뭘 언제 쓰나

| 도구 | 단위 | 메모리 | 적합한 상황 |
|---|---|---|---|
| **비동기 I/O** | — | 공유 | 파일·DB·네트워크 (기본) |
| **worker_threads** | 스레드 | 분리(공유 가능) | CPU 집약 계산 |
| **child_process** | 프로세스 | 완전 분리 | 외부 프로그램·다른 언어 |
| **cluster / pm2** | 프로세스 | 완전 분리 | 서버 자체를 코어 수만큼 (→ N-6, 9-1강) |

**의사결정 흐름**

```
느린가?
├─ I/O 때문 → 이미 비동기면 OK. Sync 함수 쓰고 있진 않은지 확인
├─ 계산 때문 → worker_threads
├─ 외부 프로그램 필요 → child_process
└─ 그냥 트래픽이 많음 → cluster / pm2 -i max
```
