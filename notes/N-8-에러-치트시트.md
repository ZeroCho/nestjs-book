# N-8. 자주 만나는 에러 치트시트

> **외우지 마세요.** 에러가 나면 여기서 Ctrl+F로 찾고, 없으면 메시지를 그대로 AI에 붙여넣으세요 (→ N-1).
> 중요한 건 에러를 안 만나는 게 아니라, **만났을 때 당황하지 않는 것**입니다.

---

## 0. 모든 에러의 기본기

1. **에러 메시지를 끝까지 읽는다** — 답이 적혀 있는 경우가 절반입니다
2. **스택 트레이스의 첫 줄 중 내 코드**를 찾는다 — `node_modules` 안쪽 줄은 대개 무시
3. 그래도 모르겠으면 메시지 전문을 검색하거나 AI에게

```
Error: listen EADDRINUSE: address already in use :::3000
    at Server.setupListenHandle (node:net:1817:16)      ← 노드 내부, 무시
    at listenInCluster (node:net:1865:12)                ← 노드 내부, 무시
    at Object.<anonymous> (/Users/me/app.js:12:5)        ← ★ 내 코드! 여기 봐야 함
```

---

## 1. 서버가 안 뜰 때

### `EADDRINUSE: address already in use`

**그 포트를 이미 뭔가 쓰고 있습니다.** 대개 이전에 띄운 서버가 안 죽었습니다.

```bash
# 맥/리눅스
lsof -i :3000
kill -9 <PID>

# 윈도
netstat -ano | findstr :3000
taskkill /PID <PID> /F
```

또는 포트를 바꾸세요: `app.listen(3001)`

### `EACCES: permission denied`

1024 미만 포트(80, 443)는 관리자 권한이 필요합니다.
→ 개발할 땐 3000·8080을 쓰고, 배포에선 nginx를 앞에 두세요 (→ N-6).

### `Cannot find module 'express'`

```bash
npm i                    # 설치가 안 됨
```

그래도 안 되면:
```bash
rm -rf node_modules package-lock.json && npm i
```

**내가 만든 파일인데** 이 에러가 난다면 → 경로 문제입니다. `./`를 빠뜨렸는지 확인하세요.
```js
require('utils')      // ❌ node_modules에서 찾음
require('./utils')    // ✅ 내 파일
```

---

## 2. 모듈 시스템 (CJS vs ESM)

### `Cannot use import statement outside a module`

`import`를 썼는데 CommonJS로 인식되고 있습니다.

```json
// package.json
{ "type": "module" }
```

또는 파일 확장자를 `.mjs`로.

### `require is not defined in ES module scope`

반대 상황. ESM에서 `require`를 쓸 수 없습니다.

```js
import fs from 'fs';        // ✅
```

`package.json`에서 `"type": "module"`을 빼거나, 파일을 `.cjs`로 바꾸세요.

### `__dirname is not defined`

ESM에는 `__dirname`이 없습니다.

```js
import { fileURLToPath } from 'url';
import path from 'path';

const __filename = fileURLToPath(import.meta.url);
const __dirname = path.dirname(__filename);
```

### `ERR_MODULE_NOT_FOUND` — 확장자 문제

ESM은 **확장자를 생략할 수 없습니다.**

```js
import { add } from './math';        // ❌
import { add } from './math.js';     // ✅
```

## 3. 비동기 / undefined

### `TypeError: Cannot read properties of undefined (reading 'xxx')`

**노드에서 가장 자주 보는 에러입니다.** 원인은 셋 중 하나.

**① await를 빠뜨렸다**
```js
const user = getUser();          // ❌ Promise 객체가 들어옴
console.log(user.name);          // undefined.name → 에러

const user = await getUser();    // ✅
```

**② 콜백 밖에서 값을 쓰려 했다**
```js
let data;
fs.readFile('a.txt', (err, d) => { data = d; });
console.log(data.toString());    // ❌ 아직 안 읽음 → undefined
```

**③ 있을 거라 가정한 값이 없다**
```js
res.json(req.user.id);           // ❌ 비로그인이면 req.user가 없음
res.json(req.user?.id);          // ✅ 옵셔널 체이닝
```

### `Cannot set headers after they are sent to the client`

응답을 **두 번** 보냈습니다.

```js
app.get('/', (req, res) => {
  if (!req.user) res.status(401).send('로그인 필요');   // ❌ return이 없음
  res.send('환영합니다');                                 // 여기까지 실행됨
});
```

```js
  if (!req.user) return res.status(401).send('로그인 필요');   // ✅
```

**`res.send`/`res.json`/`res.render` 앞에는 웬만하면 `return`을 붙이세요.**

### `UnhandledPromiseRejection`

프로미스 에러를 아무도 안 잡았습니다.

```js
app.get('/', async (req, res, next) => {
  try {
    const data = await db.find();
    res.json(data);
  } catch (err) {
    next(err);              // ✅ 에러 미들웨어로 넘김
  }
});
```

## 4. 요청 데이터

### `req.body`가 `undefined`

body 파서 미들웨어가 없거나, 라우터보다 **아래에** 있습니다.

```js
app.use(express.json());                   // ✅ 라우터보다 위에
app.use(express.urlencoded({ extended: true }));

app.post('/user', (req, res) => { ... });
```

### `req.file` / `req.files`가 `undefined`

- 멀터 미들웨어를 라우터에 안 붙였다
- 폼에 `enctype="multipart/form-data"`가 없다
- 필드 이름이 안 맞는다 (`upload.single('img')` ↔ `<input name="img">`)

### CORS 에러 (브라우저 콘솔)

```
Access to fetch at 'http://localhost:3000' from origin 'http://localhost:5173'
has been blocked by CORS policy
```

```bash
npm i cors
```
```js
const cors = require('cors');
app.use(cors({ origin: 'http://localhost:5173', credentials: true }));
```

> 쿠키를 주고받으려면 서버는 `credentials: true`, 클라이언트는 `fetch(url, { credentials: 'include' })`가 **둘 다** 필요합니다.

## 5. 데이터베이스

### `ER_ACCESS_DENIED_ERROR`

아이디/비밀번호가 틀렸습니다. `.env`의 값을 확인하세요 (→ N-2).

### `ECONNREFUSED 127.0.0.1:3306`

MySQL 서버가 안 켜져 있습니다.

```bash
brew services start mysql        # 맥
sudo systemctl start mysql       # 리눅스
```

### `ER_NO_SUCH_TABLE`

테이블이 없습니다. 마이그레이션을 실행했는지, DB 이름이 맞는지 확인하세요.

### `ER_DUP_ENTRY: Duplicate entry`

UNIQUE 제약이 걸린 컬럼에 중복 값을 넣었습니다. 회원가입 시 이메일 중복이 대표적이에요.
**에러로 터뜨리지 말고 미리 검사해서 안내 메시지를 주는 게 좋습니다.**

### `ER_DATA_TOO_LONG`

컬럼 길이를 초과했습니다. `VARCHAR(20)`에 30자를 넣는 경우.

### 한글이 `???` 로 저장됨

DB/테이블 문자셋이 `utf8mb4`가 아닙니다 (→ N-2).

## 6. 인증 / 세션

### 로그인은 되는데 새로고침하면 풀린다

- `express-session`이 라우터보다 **위에** 있는지
- `passport.initialize()`, `passport.session()`이 세션 **다음에** 오는지
- 쿠키의 `secure: true`인데 http로 접속 중인지 (개발에선 `secure: false`)

### `req.user`가 항상 undefined

`deserializeUser`가 등록 안 됐거나 그 안에서 에러가 나고 있습니다.
`console.log`를 넣어 호출 여부부터 확인하세요.

### `Failed to serialize user into session`

`serializeUser`를 등록하지 않았습니다.

## 7. TypeScript

### `Property 'user' does not exist on type 'Request'`

Express 타입을 확장해야 합니다.

```ts
// types/express.d.ts
declare global {
  namespace Express {
    interface Request {
      user?: User;
    }
  }
}
export {};
```

### `Could not find a declaration file for module 'xxx'`

```bash
npm i -D @types/xxx
```

`@types`가 없는 패키지라면:

```ts
// types/xxx.d.ts
declare module 'xxx';
```

### `Object is possibly 'undefined'`

**타입스크립트가 일을 제대로 하고 있는 겁니다.** 무시하지 말고 처리하세요.

```ts
user?.name                        // 옵셔널 체이닝
if (!user) return;                // 가드
user!.name                        // 단언 — 확실할 때만, 남용 금지
```

## 8. Nest.js

### `Nest can't resolve dependencies of the XxxService (?)`

가장 자주 만나는 네스트 에러입니다. → **N-7 노트 1장**에 자세히.

체크리스트:
1. 그 클래스가 어느 모듈의 `providers`에 있나?
2. 다른 모듈 거라면 그쪽에서 `exports` 했나?
3. 이쪽 모듈에서 `imports` 했나?

### `Cannot determine a type for the ... property`

`emitDecoratorMetadata`가 꺼져 있거나, 순환 참조입니다.

```json
// tsconfig.json
{
  "compilerOptions": {
    "emitDecoratorMetadata": true,
    "experimentalDecorators": true
  }
}
```

### 순환 의존성

```ts
@Inject(forwardRef(() => OtherService))
```
→ N-7 노트 참고. 근본적으로는 설계를 다시 보는 게 맞습니다.

## 9. 배포

### 로컬에선 되는데 서버에서 안 됨

가장 흔한 원인 순서대로:

1. **`.env`를 안 올렸다** (gitignore 되어 있으니까!) → 서버에서 직접 만들어야 함
2. 노드 버전이 다르다 → `node -v` 비교
3. `NODE_ENV=production`이라 devDependencies가 없다
4. 포트가 방화벽/보안 그룹에서 막혀 있다
5. 대소문자 — **맥은 파일명 대소문자를 구분 안 하지만 리눅스는 구분합니다.** `require('./User')`와 `./user`가 로컬에선 되고 서버에선 깨지는 고전적 함정

### pm2로 띄웠는데 바로 죽음

```bash
pm2 logs                  # ← 무조건 여기부터
pm2 logs --err            # 에러만
```

### 메모리 부족으로 죽음

```bash
pm2 start app.js --max-memory-restart 500M
```

프리티어 EC2는 메모리가 작아서 빌드 중에 죽는 일이 흔합니다. 스왑을 잡아주세요.

## 10. 그래도 안 풀릴 때

```bash
# 1. 껐다 켜기 — 진심으로 효과 있습니다
# 2. 의존성 초기화
rm -rf node_modules package-lock.json && npm i
# 3. 캐시 정리
npm cache clean --force
# 4. 최소 재현 코드 만들기 — 이 과정에서 원인을 찾는 경우가 많습니다
```

그리고 **N-1의 질문 템플릿**으로 AI에게 물어보세요.
환경 + 의도 + 코드 + 에러 전문, 이 네 가지를 주면 대부분 풀립니다.
