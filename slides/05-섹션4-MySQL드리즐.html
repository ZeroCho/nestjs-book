메모리에 있던 users가 왜 증발하는지 짚고, MySQL·워크벤치를 설치한다.

4-1 · 개념

메모리 vs 디스크

✗ 메모리 — 서버가 꺼지면 증발

✓ 데이터베이스 — 디스크에 계속 보존

라이브 코딩 · 설치

MySQL · 워크벤치 설치

  1. MySQL 설치 (윈도·맥 — 막히는 포인트 위주, 배속)
  2. 워크벤치 설치하고 커넥션 생성
  3. 접속 확인
결과 → 워크벤치에서 DB에 접속 완료. OS별 상세는 노트 N-2. “설치 막히면 에러 메시지를 그대로 AI에.”
4-2

테이블 만들고 SQL로 CRUD

16분 · 라이브 코딩 (SQL)

테이블을 만들고 순수 SQL로 데이터를 넣고·읽고·고치고·지운다.

라이브 코딩

SQL로 데이터 다루기

  1. CREATE SCHEMA / CREATE TABLE (users, comments) — 타입·PK/FK
  2. INSERT / SELECT (WHERE · ORDER BY · LIMIT)
  3. UPDATE / DELETE — 데이터는 박서연
  4. WHERE 빼먹은 UPDATE 사고 시연
결과 → 워크벤치와 SQL 양쪽으로 CRUD. “WHERE 없는 UPDATE/DELETE는 손이 떨려야 정상.”
4-2 · 개념

CRUD ↔ SQL

동작SQL
CreateINSERT INTO users ...
ReadSELECT * FROM users WHERE id=1
UpdateUPDATE users SET ... WHERE id=1
DeleteDELETE FROM users WHERE id=1

SQL을 매번 문자열로 짜기 귀찮죠? JS답게 쓰는 법이 다음 시간.

4-3

드리즐 ORM 한 방에

18분 · 라이브 코딩

ORM은 통역사. 방금 배운 SQL 지식을 그대로 자산으로 쓰는 드리즐을 익힌다.

4-3 · 개념

ORM = 통역사

SQL
SELECT * FROM users
WHERE id = 1;
Drizzle
db.select()
  .from(users)
  .where(eq(users.id, 1));
라이브 코딩

드리즐 연결부터 쿼리까지

  1. 드리즐 설치 · MySQL 연결 · 스키마를 코드로 정의
  2. 관계 정의 (1:N · N:M) + drizzle-kit으로 DB 동기화
  3. insert/select/update/delete + 조인·집계
  4. 각 코드가 어떤 SQL로 변환되는지 로그로 확인
결과 → JS로 DB를 다룬다. “통역 결과를 항상 볼 수 있어야 진짜 아는 것.” 재료 완성 → 다음 섹션부터 진짜 서비스.
