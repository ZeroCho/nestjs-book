REST API 서버 만들기

12분 · 개념 3분 + 라이브 코딩

주소마다 다른 일을 하는 서버. 주소 설계 규칙 REST를 잡고, CRUD 서버를 만든다.

2-1 · 개념

REST — 주소는 명사, 동작은 메서드

메서드의미예시
GET조회GET /users
POST생성POST /users
PUT수정PUT /users/1
DELETE삭제DELETE /users/1
라이브 코딩

CRUD 라우팅 서버

  1. restServer.js — users 객체를 DB 대용으로 (데이터: 박서연)
  2. URL·메서드로 분기해 목록/등록/수정/삭제 처리
  3. 주소 파싱이 필요해지면 URL 클래스 도입
  4. 브라우저는 GET만 가능 → fetch로 POST 쏘기
결과 → 하나의 서버가 주소·메서드에 따라 다르게 동작. “서버 끄면 users 증발 → DB가 필요한 이유(섹션 4).”
2-2

파일이 길어졌다 — 모듈로 쪼개기

10분 · 라이브 코딩 + 개념

100줄을 넘긴 파일을 쪼갠다. 노드의 두 모듈 시스템(CJS·ESM)을 실습으로 익힌다.

라이브 코딩

라우팅 로직을 파일로 분리

  1. 라우팅 로직을 별도 파일로 빼고 module.exports / require
  2. 같은 걸 export / import로 바꿔보기
  3. ESM에서 __dirname이 없어지는 것 확인 → import.meta.url
  4. 이후 강의는 한쪽 방식으로 통일 선언
결과 → 파일이 역할별로 나뉜다. 상호 호출·다이내믹 임포트는 “겪으면 책 2.4로” 안내만.
2-2 · 개념

노드엔 모듈 시스템이 둘

CommonJS (CJS)
// math.js
module.exports = { add };

// app.js
const { add } = require('./math');
ECMAScript (ESM)
// math.js
export { add };

// app.js
import { add } from './math.js';
http 모듈 노가다는 여기까지. 이 고생을 기억한 채 다음 섹션에서 익스프레스를 만나면, 프레임워크가 뭘 해주는지 정확히 보인다.
