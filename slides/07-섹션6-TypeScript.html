5-7의 폭탄을 터뜨리며 시작. 왜 타입이 필요한지 몸으로 느끼고 문법을 속성으로 익힌다.

6-1 · 연출

JS가 안 알려준 폭탄

JS — 런타임에서야 터짐
router.get('/me', (req,res)=>{
  res.json(req.user.id);
  // 비로그인 → 실행 중 크래시
});
TS — 미리 빨간 줄
// req.user: User | undefined
res.json(req.user?.id);
// undefined일 수 있음 —
// 실행 전에 경고

이 에러, 코드 짤 땐 아무도 안 알려줬다. 사용자가 겪고 나서야 안다. TS는 실행 전에 알려준다.

라이브 코딩

ts 실행 + 문법 속성 과외

  1. 노드에서 ts 파일 바로 실행 (“요즘 노드는 거의 그냥 실행”)
  2. NodeBird 전환에 필요한 것만: 기본 타입 · 인터페이스 · 유니언 · 제네릭 맛보기
  3. any를 쓰면 안 되는 이유
결과 → TS 기본기 장착. “문법 전체는 범위 밖 — 더 깊이는 공식 핸드북과 AI. 목표는 전환 완주.”
6-2

NodeBird 전환 — 에러 0개 만들기

18분 · 라이브 코딩 (일부 배속)

전환은 에러 개수를 0으로 줄여가는 게임. 처음 수백 개 떠도 정상이다.

라이브 코딩

전환 실전

  1. tsconfig · @types/* 설치 → 첫 컴파일 에러 폭탄 화면
  2. 라이브러리 타이핑: req.user에 User 타입 확장
  3. 내 코드 타이핑 — 대표 패턴 2~3개는 라이브, 나머지는 배속
  4. 에러 0개 달성 → 전체 동작 확인
결과 → 6-1의 폭탄을 이제 에디터가 미리 잡는다. “에러 200개 떠도 정상 — 하나씩 잡는 게 오늘 내용.”
