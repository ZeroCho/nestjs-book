5-2

데이터베이스 세팅

14분 · 라이브 코딩

User·Post·Hashtag 스키마와 관계를 드리즐로 정의한다. 팔로잉이 최종 보스.

5-2 · 개념

데이터 관계 3종

1 : N
유저 ↔ 글

N : M
글 ↔ 해시태그

셀프 N : M
유저 ↔ 유저

라이브 코딩

스키마와 관계 정의

  1. User · Post · Hashtag 스키마 정의
  2. 1:N(유저-글) · N:M(글-해시태그) · 셀프 N:M(팔로잉) 관계 (4-3 회수)
  3. DB 생성 · 연결 확인 → 커밋
결과 → 관계까지 갖춘 DB 완성. “팔로잉은 유저가 유저를 팔로우 → 자기 자신과 N:M.”
5-3

로그인 ① 회원가입·해싱·환경변수

16분 · 라이브 코딩

로그인은 서버 개발 종합 격투기. 지금까지 배운 게 총출동한다.

라이브 코딩

안전한 회원가입 만들기

  1. Passport 전체 구조 그림을 머리에 넣고 시작
  2. 회원가입을 평문 비밀번호로 먼저 → DB에 그대로 보이는 화면
  3. bcrypt 해싱 도입 (단방향 → 복호화가 아니라 대조)
  4. 비밀키 하드코딩 → process.env + dotenv (5-1의 .gitignore 회수)
결과 → 박서연 계정 생성. “평문 저장은 범죄에 가깝다. 깃허브에 키 올라가는 사고, 진짜 많다.”
5-3 · 코드

비밀번호는 해싱

✗ 평문 저장
db.insert(users).values({
  email,
  password: password,
});
✓ bcrypt
const hash =
  await bcrypt.hash(password, 12);
db.insert(users).values({
  email,
  password: hash,
});
5-4

로그인 ② Passport 전략과 세션

15분 · 라이브 코딩

Passport 최대 고비 serialize/deserialize를 두 문장으로 넘는다.

5-4 · 개념

serialize / deserialize

  • serialize = 유저에서 열쇠(id)만 뽑아 세션에 넣기
  • deserialize = 매 요청마다 열쇠로 유저를 다시 찾아오기
라이브 코딩

로컬 로그인 완성

  1. LocalStrategy 작성
  2. serializeUser / deserializeUser (3-2 세션 회수)
  3. isLoggedIn / isNotLoggedIn 미들웨어
  4. 로그인 · 로그아웃 동작 확인 → 커밋
결과 → 로그인 상태가 유지된다. “이 미들웨어를 어디에 꽂느냐가 전부 수동 규칙 — 섹션 7에서 가드로 바뀐다.”

카카오 로그인

12분 · 라이브 코딩

비밀번호를 아예 안 받는 OAuth 방식. Strategy만 갈아끼우면 된다.

라이브 코딩

OAuth 로그인 붙이기

  1. OAuth 흐름 그림 3분 — “우리 서버는 비밀번호를 안 받는다”
  2. 카카오 개발자 앱 등록
  3. KakaoStrategy + 콜백 라우터
  4. 로그인 동작 확인 → 커밋
결과 → 카카오로 로그인 완료. “구글·네이버도 패턴은 같다 — Strategy 갈아끼우기. 하나 하면 나머지는 문서로.”

멀터로 이미지 업로드 + 해시태그

13분 · 라이브 코딩

파일 업로드는 body-parser가 못 한다. multipart 전용 미들웨어 멀터가 필요.

라이브 코딩

이미지와 해시태그

  1. 멀터 설정 (저장 경로 · 파일명 · 용량 제한)
  2. 이미지 업로드 라우터 + 글 작성 연결 + 미리보기
  3. 정규식으로 해시태그 추출 → N:M 관계에 저장 (5-2 회수)
  4. 커밋
결과 → 이미지 달린 글과 해시태그 완성. “글자만 있는 SNS는 심심하니까.”
