npm과 익스프레스 시작하기

14분 · 개념 + 라이브 코딩

남의 코드를 가져다 쓰는 npm을 익히고, 2-1의 서버를 익스프레스로 포팅해 before/after를 본다.

라이브 코딩

npm으로 익스프레스 설치

  1. npm init → package.json 필드 훑기
  2. npm i express → node_modules·lock 파일 관찰
  3. node_modules 지우고 npm i로 복원 → “그래서 깃엔 안 올림”
  4. app.js로 2-1 REST 서버를 익스프레스로 포팅
결과 → 같은 동작을 훨씬 짧은 코드로. SemVer의 ^만 짚고, 나머지 npm 명령어는 노트 N-3.

3-2

미들웨어 총정리

20분 · 라이브 코딩 + 쿠키/세션 개념

익스프레스의 심장 미들웨어를 하나씩. 쿠키·세션 개념도 여기서 압축해 흡수한다.

3-2 · 개념

미들웨어 = 공항 입국 심사대

app.use((req, res, next) => {
  // 여권 검사…
  next();   // 안 부르면 여기서 멈춤!
});
라이브 코딩

미들웨어를 붙여 나간다

  1. app.use로 직접 미들웨어 작성 → next() 빼먹으면 멈추는 것 시연
  2. morgan(로그) · static(1-3의 fs 고생 회수) · express.json · cookie-parser
  3. 쿠키를 개발자도구 Application 탭에서 확인 → 직접 조작해 보이기
  4. express-session 적용 → 민감한 건 서버, 열쇠만 쿠키
결과 → 우리가 손으로 한 것마다 미들웨어가 하나씩. 순서가 곧 로직(static은 session 위에).
3-2 · 개념

서버는 방금 온 사람을 기억 못 한다

쿠키 — 브라우저에는 조작 가능한 작은 열쇠

세션 — 민감한 정보는 서버 금고에 보관

이 “열쇠만 맡긴다” 구조가 5-4의 Passport serialize/deserialize로 이어진다.

3-3

라우터 분리, 404, 에러 처리

14분 · 라이브 코딩 + 예외 처리

길어진 라우팅을 폴더로 나누고, 서버가 죽는 경험을 통해 예외 처리를 흡수한다.

라이브 코딩

구조 잡고 에러 방어하기

  1. routes/ 폴더로 라우터 분리 (2-2 모듈 회수) + 라우트 매개변수
  2. 맨 아래 404 미들웨어 + 에러 처리 미들웨어
  3. 일부러 에러를 내서 서버가 죽는 것 확인 → try/catch로 방어
  4. uncaughtException은 최후의 방어선일 뿐임을 강조
결과 → 에러가 나도 서버가 살아남는다. “프런트 에러는 그 사람 화면만, 서버 에러는 전원 접속 불가.”
3-3 · 개념

에러 처리 미들웨어는 맨 아래

app.use('/', indexRouter);
app.use('/user', userRouter);

app.use((req, res) => {          // 404: 아무 라우터도 못 잡으면
  res.status(404).send('Not Found');
});

app.use((err, req, res, next) => {  // 인자 4개 = 에러 전용
  console.error(err);
  res.status(500).send('서버 에러');
});

req/res 자주 쓰는 것은 치트시트로. 에러 목록은 노트 N-8 — “외우지 말고 메시지를 AI에.”
